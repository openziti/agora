## Things the tree won't tell you

- **Why unresolved ID-as-name rows exist.** `agora tunnel connect <tt_id>` sends the token only as `Name`; the saved row keeps that literal name even after the runtime backfills `TunnelID` on first success. So a `tt_…` reference has to match by stored ID *and*, for rows that never resolved, by exact literal name.
- **Online removal sends exactly one identifier per row.** The saved desired tunnel ID when present, otherwise the saved name, plus the listen address. This alone was insufficient: the runtime put both identifiers back into its internal removal call. The closeout correction below makes differing resolved IDs authoritative throughout connect matching. Attachment ID stays empty because heartbeat recovery can swap it between list and remove. `ManagedConnectStatus.TunnelId` always equals `Desired.TunnelId` today (`actor.tunnelID` is set alongside `desired`); selection falls back to it only defensively, and removal never keys on it.
- **Deliberate non-action:** after a successful daemon probe, a list or remove failure never falls back to editing `network.json`. Rerunning is the recovery.
- **`delete connect` is now `RunE` with the recover-to-error wrapper** used by `tunnel connect`/`serve`/`create`. Single-address failures that used to panic with a stack trace now print as errors. The cobra `Error:` + usage + `main`'s `error:` double print is shared with those siblings and was left alone.
- **`go test -race ./sdk/agent` fails on a pre-existing race** in `df/dl` lazy init (`ensureInit`), which existing tests such as `TestAgentRestoresDesiredServeAndConnectOnStart` also trip. It's unrelated to this change. The plain suite passes.

## Terminus round 1 (review `1802372e5888`): dispositions

- **`bulk-connect-persist-rollback`: accepted, scope expansion authorized by Michael.** When the write failed, `removeConnectActor` put the actor back but not its `a.network.Connects` row. `ListConnects` iterates `a.network.Connects`, so the connect kept running while staying invisible to a rerun of `--all`. It now restores the previous slice (`removeConnect` builds a new slice, so the old one is untouched). `TestAgentRemoveConnectPersistFailureKeepsConnect` covers it and fails without the restore. The identical serve-side flaw is left unchanged by direction and tracked in `docs/future/roadmap/removeserveactor-loses-desired-serve-when-persistence-fails.md`.
- **`bulk-connect-ambiguous-daemon`: accepted, fixed narrowly for `--all`, work order revised by Michael.** `normalizeDialError` folds timeouts, cancellation, and every gRPC `Unavailable` into `ErrNotRunning`, and gRPC flattens the dial error into a status string, so the socket errno can't be recovered from the ping error without parsing text. When the probe fails that way, `confirmNetworkAbsent` (`cmd/agora/tunnelDelete.go`) checks the socket itself: `Lstat` not-exist, or a direct unix dial that fails with not-exist or `ECONNREFUSED`, permits the offline edit. Windows reports a stale socket as `WSAECONNREFUSED` (10061), which `syscall.ECONNREFUSED` does not match there, so it's checked explicitly. That branch compiles under `GOOS=windows go vet` but was not exercised on Windows; if it's wrong, the command fails closed. A socket that accepts is an error. The shared daemon client is unchanged. A daemon starting between the socket check and the write stays uncoordinated (out of scope per the spec). Tests: `TestConfirmNetworkAbsent` and `TestBulkConnectRouting` (silent, closing, missing, and stale sockets); the ambiguous cases fail with the gate removed. The single-address commands' equivalent fallback is tracked in `docs/future/roadmap/delete-commands-edit-network-json-behind-a-daemon-that-may-be-running.md`.

## Closeout review: overlapping connect names

- Terminus `a00a07a20f82` found one blocker, `bulk-connect-overlapping-name`: `removeConnectActor` passed both the selected actor's ID and name into an either/or matcher, allowing removal of a different ID's desired row when name and listen address overlapped. The same matcher could pair a listed row with the wrong actor.
- Michael authorized the narrow correction. `matchesConnect` now compares ID plus listen address when both sides carry resolved IDs, retaining name matching for unresolved entries and name-only requests. The bulk-removal daemon regression now gives the retained connection the same name and listen address as a removed one, verifies listed identities, retained running state, persistence, and restart. Both regressions failed before the matcher correction.

The replay therefore used two deleted generations to keep the collision stable. This correction changes only local identity matching, not controller lookup semantics.
