## Things the tree won't tell you

- **`session-<ses_id>` is the controller's tunnel name** (`acceptSession.go`), and the SDK transport reuses the same string for its in-memory actor name. A `session-ses_…` row in a daemon's `network.json` is what `agora tunnel connect session-ses_X` produces; it is not evidence the session SDK wrote it. The SDK path cannot write that file: `a.Runtime()` is only ever a `NewEmbedded` runtime with `root: nil`. Confirmed live with a daemon running on the same enrollment.
- **The only source-level route to a rooted embedded runtime is `Runtime.ReloadEnvironment`**, which sets `a.root` unconditionally. It is exported but only reachable over the daemon's gRPC. Deliberately not "fixed"; flagged as a question for the reporter.
- **A dead row with a populated tunnel id connected successfully at least once.** `tunnel_id` is only backfilled on first success (`updateConnectDesired`); a connect that failed from the start persists with an empty id. Useful when reading field `agora status` output.
- **SDK listen ports are kernel-ephemeral** (`pickEphemeralLoopbackPort` binds `:0`). Field rows on `84xx` ports were chosen by some caller.

## Live-repro gotchas

- Isolated roots work via `AGORA_ENV_ROOT` / `--env-root`, but `agora network start` fails with `bind: invalid argument` when the root path pushes `network.sock` past 108 bytes. Use a short symlink.
- A detached worktree has no `ui/dist`; build with `-tags no_agora_ui`.
- `agora session propose` returns at `proposed`, so a connect issued right after it hits `tunnel not found` — and still persists a row. `session close` has no `--yes`. Both contradict `sessions.md` (roadmap card `sessions-doc-cli-drift`).
- A harness consumer that exits on error without `Close` leaves the session `active`; CLI connects to its tunnel then look like they "survived close". Check `agora session describe` before reading anything into a running row.
- Test accounts that acted as SDK session providers cannot be deleted until their leaked standalone `session-ses_…` tunnels are removed (roadmap card `session-provider-re-creates-closed-session-tunnels-as-standalone-tunnels`). Re-enable an environment for the account, `agora tunnel delete` each, then delete the account.
