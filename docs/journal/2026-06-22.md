# 2026-06-22 — Account-owned tunnels implementation

Implementing `docs/future/account-owned-tunnels.md` + work order on branch `standalone-tunnel-lifecycle`. Pacing in three seams with a check-in after each. Verification scope this pass: `go build/vet/test ./...` (testcontainers ok; Docker available); live OpenZiti fabric verification deferred to the user.

## Core model
- **Discriminator:** `tunnels.environment_id` NULL = standalone (account-owned); set = Layer 2 session tunnel. No new column. Everything (retire survival, takeover eligibility) keys off this.
- Automation/fabric package lives at `internal/fabric/openziti/automation/` (work order's bare `automation/` is shorthand). `ServicePolicyManager` (`service_policy.go`) is the template for the new `TerminatorManager`; generic helpers `filterValue`/`BuildFilter`/`deleteWithFilter`/`wrapError`/`IsNotFound`/`oneResult` are reusable.

## Seam 1 done (schema + persistence)
- Migration `0012_account_owned_tunnels.sql`: drop NOT NULL on `environment_id`; add `environments_id_account_organization_unique`; swap the org-scoped CASCADE env FK for an account-scoped NO ACTION FK `(environment_id, account_id, organization_id)`.
- `Tunnel.EnvironmentID` is now `*string`.

### Load-bearing facts for later seams
- **`Environments.Delete` is a SOFT delete** (`deleted=true`). The DB env-FK cascade therefore only ever fired on **hard** tenant teardown (account/org delete), never on environment retire — retire's tunnel deletion is done by the `disableEnvironment.go` controller loop, not the DB.
- **NO ACTION env FK blocks a raw `DELETE FROM environments` while a session tunnel (env set) references it.** This is why the retire handler must tear down session tunnels *before* deleting the env row. Standalone tunnels (NULL env, MATCH SIMPLE) are exempt and survive.
- **C3 cascade**: deleting an account (`Accounts.Delete` is a hard `DELETE`, maps FK violations to `ErrConflict`) cascade-deletes its environments AND its tunnels/serves/attachments in one statement, so the NO ACTION FK never blocks it. `Organizations.Delete` refuses (`ErrConflict`) while any account remains — org is emptied account-by-account.

## Seam 2 done (controller + fabric + API contract)
**Sequencing change from plan:** the API spec + REST regen (Slice 9) was pulled forward into Seam 2 because the `takeoverTunnel` controller handler implements the ogen `Handler` interface and can't compile without the regenerated types. Seam 3 is now just CLI + SDK proto + docs.

- `internal/fabric/openziti/automation/terminator.go`: `TerminatorManager` (Find/Delete over `terminator.ListTerminators`/`DeleteTerminator`, server-side `Filter`), registered as `Client.Terminators`. `TunnelProvisioner` gained `EvictTerminatorsByService` (takeover) / `EvictTerminatorsByIdentity` (retire); both exposed on the `tunnelLifecycle` interface.
- Bind policy is now account-scoped: `TunnelSpec.EnvironmentIdentityID` → `BindIdentityRoles []string`; bind policy renamed `<svc>-bind`. Standalone create passes `["#agora-account:<id>"]`; `acceptSession` passes `["@<envIdentity>"]` (session stays env-scoped).
- `createTunnel` env-optional: a supplied `environmentId` is validated-then-discarded; the row is **always** `EnvironmentID=nil` (R2-A1).
- Serve eligibility (`tunnelServeLifecycle`): env-match rejection replaced with owning-account check (`env.AccountID/OrganizationID == tunnel...`).
- `takeoverTunnel.go`: `POST /tunnels/{tunnelId}/takeover` (204), shape-agnostic eviction primitive (delete terminators by service + clear active serve record); **rejects session tunnels (env set) before any mutation** (R2-C1).
- Retire (`disableEnvironment`): explicit `EvictTerminatorsByIdentity(env.ZitiIdentityID)` before identity deletion (C2).
- `deleteAccount`: refuses (`ErrConflict`, sentinel `errAccountOwnsStandaloneTunnels`) while the account owns any standalone tunnel; new `Tunnels.HasStandaloneByAccount` (R2-C2).

### Behavior flips that broke existing tests (now correct)
- `TestServiceHTTPFlow` / `TestAdmissionEnvironmentLockSerializesCreateTunnelAgainstDisable` asserted the old "tunnel deleted on env disable" — updated to assert the standalone tunnel **survives** (and `TestServiceHTTPFlow` now deletes the tunnel before the account, since the new guard refuses otherwise).
- Three SDK reuse/listen checks keyed on env-binding (`existing.EnvironmentId != environmentID`, `validateListenTunnel(tunnel, envID)`) were obsolete under account ownership — reuse now scopes to `ListTunnelsScopeOwned`; direct-tunnel listen eligibility is enforced server-side by the account bind policy, not the client.

### Watch out
- `api.Tunnel.EnvironmentId` and `api.CreateTunnelRequest.EnvironmentId` are now `OptString` (were required strings). Every other `*.EnvironmentId` on the API surface (ConnectTunnelRequest, AcceptSessionRequest, StartTunnelServeRequest, TunnelAttachment, TunnelServe, params) is **still a plain string** — don't blanket-convert.
- The controller test harness (`createOrgWithAccount`/`addAccountToOrg`) only makes **member**-role accounts, so the explicit owning-account *Conflict* edge (admin serving another account's tunnel) isn't reachable there; cross-account hosting is realistically blocked one layer earlier at `requireManagedTunnel` (NotFound). Test targets that.
